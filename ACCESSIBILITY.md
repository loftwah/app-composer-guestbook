# Accessibility

We aim for WCAG 2.2 AA. This is a target, not a certification. Use semantic HTML, native controls, labelled inputs, visible keyboard focus, adequate contrast, reduced-motion preferences, mobile layouts and saved dark/light themes. Ctrl/Cmd+K opens app navigation; the All apps link supplies the same destinations without a shortcut.

Release checks include representative phone and desktop interactions in both themes and keyboard paths. Physical devices and assistive-technology combinations require their own acceptance evidence; a browser screenshot cannot prove those.

Report a barrier in a GitHub issue with the page/action, expected behavior and relevant browser, device or assistive technology. Screenshots are optional. Do not include private account information. Accessibility improvements are welcome through ordinary contributions.
